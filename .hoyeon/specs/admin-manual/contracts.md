# Contracts — 관리자 사용 설명서 (admin-manual)

문서 산출물의 cross-cutting 불변식. 모든 챕터/캡처/PDF가 이 약속을 지켜야 일관된 메뉴얼이 된다.

## Chapter Template (모든 챕터 동일 구조)

각 챕터(= 관리자 섹션 1개)는 아래 순서를 따른다:

1. **섹션 개요** — 1~2문장, "여기서 무엇을 하는 곳인지"
2. **기능별 사용법** — 기능마다: `화면 캡처` → `① 이 버튼 클릭 → ② 입력 → ③ 결과` 동선
3. (해당 시) **⚠️ 한 줄 경고** — 위험 작업 바로 밑
4. (해당 시) **이미지 규격 박스** — 업로드 기능이 있는 챕터만

## Warning Rule (위험 작업 경고)

- ⚠️ 경고는 **정확히 3개 작업에만** 붙인다: 회원 계정 삭제 / 과제 데이터 전체 초기화 / 강의·영상 삭제
- 형식: 해당 사용법 바로 아래 **한 줄**. 별도 경고 챕터 금지.
- 그 외 삭제 작업(쿠폰·팝업·가이드·카테고리 등)은 경고 없이 사용법만.

## Capture Convention (캡처 일관성)

- 캡처 방식: **브라우저 자동화** (재현 가능, 화면 변경 시 재촉영 저비용)
- 캡처 원본은 **챕터별 폴더 분리** 보관 → 한 장씩 교체 가능 (통짜 PDF 재작업 금지)
- 캡처 해상도/뷰포트는 전 챕터 동일하게 고정 (일관된 룩)
- 캡처에 노출되는 학생 실명/연락처는 **데모 마스킹** 처리 (admin `demoMask()` 활용 또는 후보정)

## Scope Invariant

- 문서화 대상: **8개 섹션** (강의·회원·결제·과제채점·QnA·쿠폰·팝업·가이드)
- 제외: 알림톡, 배송/주문 — 캡처/설명 어디에도 등장하지 않는다

## Closing Invariant

- 메뉴얼 마지막에 비용 고지 1블록: **기존 기능 수정 = 20만원 / 신규 기능 추가 = 별도 협의**
