# Requirements

## R-B1: 대상 독자와 목적
- behavior: 메뉴얼은 비개발자 클라이언트(운영자)가 혼자 따라 할 수 있는 수준으로 작성된다.

#### R-B1.1: 클라이언트 자가 운영
- given: 클라이언트가 관리자 페이지를 직접 운영하는 상황
- when: 특정 작업 수행 중 막혔을 때 메뉴얼을 펴봄
- then: 추가 문의 없이 메뉴얼만으로 해당 작업을 완료할 수 있다

#### R-B1.2: 문의 차단 방패 역할
- given: 메뉴얼이 클라이언트에게 전달된 상태
- when: 자주 발생하는 운영 질문이 생김
- then: 메뉴얼의 해당 챕터가 그 질문에 직접 답하여 제작자에게 오는 문의를 줄인다

## R-B2: 커버 범위 — 관리자 8개 섹션
- behavior: 알림톡·배송을 제외한 관리자 8개 섹션을 빠짐없이 문서화한다.

#### R-B2.1: 8개 섹션 전체 포함
- given: 관리자 페이지에 총 10개 섹션이 존재
- when: 메뉴얼 챕터를 구성할 때
- then: ①강의 ②회원 ③결제 ④과제채점 ⑤QnA ⑥쿠폰 ⑦팝업 ⑧가이드(FAQ) 8개를 포함하고, 알림톡·배송은 제외한다

## R-B3: 완료 조건
- behavior: 8개 섹션 문서화 + 이미지 규격 명시가 모두 충족되어야 완료다.

#### R-B3.1: 전 섹션 문서화
- given: 메뉴얼 제작 완료 시점
- when: 산출물을 검수
- then: 8개 섹션 각각이 캡처 + 사용법 설명으로 문서화되어 있다

#### R-B3.2: 이미지 규격 명시
- given: 메뉴얼 제작 완료 시점
- when: 산출물을 검수
- then: 썸네일·팝업 이미지 규격 2종이 올바른/잘못된 예시와 함께 명시되어 있다

## R-B4: 수정·추가 비용 고지
- behavior: 메뉴얼 말미에 향후 수정/추가 작업의 비용 기준을 명시한다.

#### R-B4.1: 비용 안내 문구
- given: 메뉴얼의 마지막 페이지/섹션
- when: 클라이언트가 향후 변경을 검토할 때
- then: "기존 기능 수정 = 20만원, 신규 기능 추가 = 기능에 따른 별도 협의 필요"가 명시되어 있다

## R-U1: 메뉴얼 구조 (페이지 중심 투어)
- behavior: 챕터를 관리자 섹션과 1:1로 매핑한 페이지 중심 투어 형태로 구성한다.

#### R-U1.1: 챕터 = 섹션 1:1
- given: 8개 섹션 커버 범위
- when: 목차를 구성할 때
- then: 각 관리자 섹션이 하나의 챕터가 되어 총 8개 챕터로 구성된다

#### R-U1.2: 챕터 내부 = 캡처 + 클릭 동선
- given: 한 챕터를 작성할 때
- when: 특정 기능의 사용법을 설명
- then: 화면 캡처와 함께 "이 화면 → 이 버튼 → 이 결과" 순서의 클릭 동선으로 기술한다

## R-U2: 이미지 규격 안내
- behavior: 클라이언트가 직접 올리는 이미지의 정확한 규격을 코드 기준으로 안내한다.

#### R-U2.1: 강의 썸네일 규격
- given: 클라이언트가 강의 썸네일을 업로드하는 상황
- when: 강의 챕터에서 썸네일 업로드를 설명
- then: "16:9 비율, 권장 800×450px, 업로드 시 자동 WebP 변환(최대 800×600)"을 명시한다

#### R-U2.2: 팝업 이미지 규격
- given: 클라이언트가 팝업 이미지를 업로드하는 상황
- when: 팝업 챕터에서 이미지 업로드를 설명
- then: "가로 800px 권장, JPG·PNG·WebP만, 5MB 이하, 세로가 너무 길면 잘림"을 명시한다

#### R-U2.3: 올바른/잘못된 예시 쌍
- given: 이미지 규격을 설명하는 지점
- when: 규격 수치를 제시할 때
- then: 규격을 지킨 예시와 비율을 어겨 잘린 예시를 이미지 쌍으로 함께 보여준다

## R-U3: 위험 작업 ⚠️ 한 줄 경고
- behavior: 되돌릴 수 없는 작업 3개에만 한 줄짜리 경고를 사용법 바로 밑에 붙인다.

#### R-U3.1: 3개 작업 경고
- given: 데이터가 광범위하게 영구 소멸하는 작업(회원 계정 삭제 / 과제 데이터 전체 초기화 / 강의·영상 삭제)
- when: 해당 작업의 사용법을 설명한 직후
- then: ⚠️ 한 줄 주의 문구를 붙이되 별도 경고 챕터는 만들지 않는다

## R-U4: 전달 형식 (PDF)
- behavior: 최종 산출물은 PDF이며, 캡처 원본은 교체 가능하게 분리 보관한다.

#### R-U4.1: PDF 1부 산출
- given: 메뉴얼 제작 완료
- when: 클라이언트에게 전달
- then: 캡처와 설명이 통합된 PDF 1부로 전달된다

#### R-U4.2: 캡처 원본 분리 보관
- given: 향후 일부 화면이 바뀔 가능성
- when: 캡처 이미지를 관리할 때
- then: 캡처 원본을 챕터별 폴더로 분리 보관하여 통짜 재작업 없이 한 장씩 교체 가능하게 한다

## R-T1: 이미지 규격 사실 (코드 확정값)
- behavior: 메뉴얼에 적는 규격 수치는 추측이 아니라 코드에서 추출한 실제 값을 근거로 한다.

#### R-T1.1: 썸네일 렌더링/처리 근거
- given: 썸네일 규격 안내 수치
- when: 정확성을 검증할 때
- then: `courses.html:77`(16:9 표시) 및 업로드 핸들러 `admin.html:4461-4496`(WebP·최대 800×600 변환)에 근거한다

#### R-T1.2: 팝업 렌더링/검증 근거
- given: 팝업 규격 안내 수치
- when: 정확성을 검증할 때
- then: `js/popup-notice.js:64`(모달 max-width 400) 및 `admin.html:6938`(5MB 검증, JPG/PNG/WebP)에 근거한다
